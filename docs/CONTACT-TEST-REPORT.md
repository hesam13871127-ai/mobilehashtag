# گزارش آزمون به‌روزرسانی تماس و بهبود ظاهری

این گزارش مربوط به به‌روزرسانی روی نسخهٔ تأییدشده با کامیت مبنا `6a9b6b9` است. گزارش قبلی در `TEST-REPORT.md` برای سابقه حفظ شده است.

## نتیجهٔ اجرای نهایی

| آزمون | نتیجه |
|---|---|
| API + اعتبارسنجی تنظیمات (`npm test`) | **۳۵ از ۳۵ موفق**؛ ۲۸ API و ۷ آزمون مستقل تنظیمات؛ ۴.۳۸ ثانیه |
| مرورگر (`ARENA_BROWSER=1 npm run test:ui`) | **۱۴ از ۱۴ موفق**؛ بدون skipped/flaky؛ ۸۶.۱۳ ثانیه |
| `npm audit` | **۰ آسیب‌پذیری گزارش‌شده** در زمان اجرا |
| `npm run format:check` | موفق |
| `git diff --check` برای تغییرات این نوبت | موفق |
| بررسی حفظ نسخهٔ مبنا | **۱۲۴ فایل محافظت‌شده بدون تغییر بایتی**؛ تمام ۲۱ مسیر HTML حفظ شده‌اند |

محیط اجرا: Linux x64، Node.js 22.22.3، Chromium 153 headless و Playwright. هشدار experimental SQLite در Node مشاهده شد و مانع اجرا نبود.

## موارد جدیدی که واقعاً آزموده شدند

### اطلاعات مرکزی و ایمنی نمونه‌ها

- endpoint عمومی `/api/store/contact` با `no-store` اطلاعات تنظیم‌شده را برمی‌گرداند.
- شماره‌ها، ایمیل و شبکه‌های اجتماعی نمونه مقدار نمایشی دارند اما `href=null` است.
- شماره‌های نمونه از بازهٔ رزروشده و دامنه‌ها از `.example` هستند؛ مقصد تصادفی متعلق به شخص دیگری ساخته نشده است.
- تبدیل ارقام فارسی/عربی، حذف جداکننده‌های مجاز و تبدیل شمارهٔ داخلی ایران به قالب بین‌المللی.
- ساخت دقیق `tel:+…` و `https://wa.me/…` بدون `+` یا فاصله در مسیر واتساپ.
- تغییر mode به live به‌تنهایی شمارهٔ رزروشده یا دامنهٔ نمونه را فعال نمی‌کند.
- فیلد خالی/نامعتبر حذف می‌شود؛ فیلدهای ناشناخته و محرمانهٔ config منتشر نمی‌شوند.
- URLهای ناامن، hostname نامرتبط، credentials و query/hash نامعتبر لینک فعال نمی‌سازند.
- نقشه فقط در حالت live با verified=true و مختصات عددی در بازهٔ مجاز ایجاد می‌شود؛ صفر عددی با null اشتباه گرفته نمی‌شود.

### صفحه تماس و فرم

- شش کارت اطلاعات، نشان آزمایشی و نبود نقشهٔ جعلی در حالت تحویلی.
- نمایش یکسان تمام اطلاعات با پاسخ API در صفحه تماس و فوتر.
- اعتبارسنجی مرورگر برای فرم خالی، ایمیل نادرست و پیام کوتاه.
- پاسخ 400 سرور برای نام/ایمیل/پیام نامعتبر و ثابت ماندن تعداد رکوردهای contacts.
- ارسال معتبر از مرورگر، پاسخ واقعی 201 و نمایش اعلان ذخیره در پایگاه داده.
- متن ورودی مانند `<img ...>` به شکل متن نمایش داده می‌شود، نه عنصر HTML قابل اجرا.

### صفحه اصلی، فوتر و header

- نمایش شماره، واتساپ، نشانی و ساعات مرکزی در بخش جدید خانه؛ لینک صفحه تماس کار می‌کند.
- غیرفعال بودن دکمه واتساپ نمونه و نبود anchor با tel/mailto/wa.me برای اطلاعات نمونه در DOM.
- میانبر header در نمونه به صفحه تماس می‌رود، نه به شمارهٔ ساختگی.
- در پاسخ mock حالت live، لینک‌های tel، wa.me، mailto و شبکه‌های اجتماعی در محل درست ساخته می‌شوند و لینک‌های بیرونی `noopener noreferrer` دارند.
- هیچ تماس تلفنی، پیام واتساپ، ایمیل یا درخواست بیرونی برای تأیید حساب اجتماعی ارسال نشده است. آزمون live فقط ساخت و نمایش URL را بررسی می‌کند، نه مالکیت یا تحویل پیام.
- حالت تنظیمات خالی، کارت خالی یا لینک شکسته نمی‌سازد؛ فرم تماس باقی می‌ماند.
- در پاسخ خطای آزمایشی 503 برای تنظیمات، fallback تماس نمایش داده شد و افزودن محصول به سبد همچنان موفق بود.

در مسیرهای عادی تست تماس، خطای uncaught JavaScript یا پاسخ HTTP ناموفق مشاهده نشد. تمام مقصدهای HTML داخلی موجود در صفحه تماس نیز درخواست شدند و پاسخ 200 دادند. خطای 503 فقط در سناریوی تزریق خطا عمداً ایجاد شد.

اسکرین‌شات‌های تماس desktop/mobile، بخش تماس خانه و فوتر برای بازبینی بصری گرفته شدند. فوتر پس از بازبینی با یک توضیح آزمایشی مشترک به جای تکرار در تک‌تک سطرها جمع‌وجور شد؛ متن کامل و URLهای نمونه در صفحه تماس باقی ماندند.

## رگرسیون فروشگاه

هر ده سناریوی مرورگر قبلی و ۲۶ آزمون API قبلی دوباره اجرا شدند، شامل:

- تمام ۲۱ سند HTML و ۲۲ URL نماینده در پنج اندازه؛ کنترل بارگذاری تصاویر.
- همه ۴۷ دسته با حداقل یک محصول، جست‌وجو، فیلترها، sort، صفحه‌بندی و مگامنو.
- گالری، بزرگ‌نمایی، علاقه‌مندی، تغییر تعداد، سبد پایدار، تأیید حذف و حالت خالی.
- ثبت‌نام/ورود/خروج، نشانی، پروفایل و تغییر رمز.
- مسیر کامل خرید موبایل، ثبت سفارش واقعی SQLite در حالت demo، کنترل موجودی و idempotency، تاریخچه و پیگیری.
- رندر سبد پُر، checkout، حساب و جزئیات سفارش در هر پنج اندازه.
- جداسازی حساب‌ها، CSRF، قیمت سمت سرور و rollback موجودی.
- بازیابی نشست و سبد در process تازه با همان دیتابیس و کلید نشست.

فایل schema و seed، تصاویر/بنرها/لوگو، و فایل‌های اصلی کاتالوگ و منطق خرید با نسخهٔ مبنا مقایسه شدند و تغییر نکرده‌اند. تعداد محصولات **۲۸**، دسته‌ها **۴۷** و اسناد HTML **۲۱** باقی مانده است. هیچ reset یا migration دیتابیس اصلی اجرا نشده است؛ آزمون‌ها دیتابیس مجزا دارند.

## محدودیت‌ها

- آزمون Windows واقعی، Safari/Firefox، گوشی فیزیکی، بررسی بار و ممیزی جامع امنیت/دسترس‌پذیری انجام نشده‌اند.
- اطلاعات تماس واقعی و موقعیت تأییدشده هنوز در اختیار نیست؛ نمونه‌ها به تماس قابل‌استفاده با فروشگاه واقعی تبدیل نشده‌اند.
- حالت live و کارت نقشه با fixture/mock آزمایش شدند؛ مختصات fixture موقعیت فروشگاه نیست و در تنظیمات تحویلی وجود ندارد.
- پرداخت، ارسال، ایمیل و پیامک واقعی مانند قبل متصل نیستند. فرم تماس تنها ذخیره می‌کند.
- صفر مورد در audit به معنی تضمین امنیت مطلق نیست.

## بازتولید

## آزمون ZIP کامل استخراج‌شده

بستهٔ جدید در پوشه‌ای جدا از پروژه استخراج و روی Linux آزمایش شد:

1. کنترل CRC همه فایل‌ها و وجود config، renderer، سورس کامل و مستندات جدید؛ نبود `.env`، دیتابیس شخصی و `node_modules` در ZIP.
2. اجرای تازهٔ `npm ci --omit=dev` و `npm run setup` در همان پوشهٔ استخراج‌شده، بدون استفاده از وابستگی‌های پروژهٔ اصلی.
3. پاسخ موفق خانه و صفحه تماس، دریافت ۲۸ محصول، ۴۷ دسته و تنظیمات نمونه با لینک‌های غیرفعال و map=null.
4. ارسال فرم تماس و بررسی ذخیره واقعی یک رکورد در contacts.
5. ساخت حساب، سبد و سفارش آزمایشی واقعی با مبلغ ۵۵۹٬۰۰۰ تومان؛ همان رفتار خرید نسخه قبل.
6. تغییر ساعات کاری و خالی کردن ایمیل **فقط در کپی آزمایشی config**؛ API بدون restart مقدار تازه و email=null برگرداند.
7. خراب کردن عمدی JSON **فقط در کپی آزمایشی**؛ endpoint تماس 503 داد ولی API محصولات همچنان ۲۸ محصول برگرداند. سپس فایل آزمایشی به حالت اصلی بازگردانده شد.

نتیجه: **موفق**. تنظیمات و دیتابیس پروژهٔ اصلی در این آزمون تغییر داده نشدند. پس از افزودن این گزارش، ZIP نهایی دوباره ساخته و صحت آرشیو آن کنترل شد؛ تنها تفاوت با بستهٔ smoke-test، متن تکمیلی همین گزارش است.
