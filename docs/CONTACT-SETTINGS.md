# تنظیم اطلاعات تماس موبایل هشتگ

## تنها فایل تنظیمات

```text
backend/config/contact.json
```

نام فروشگاه، شماره تماس، واتساپ، نشانی، ایمیل، ساعات کاری، اینستاگرام، تلگرام و تنظیم نقشه فقط در این فایل قرار دارند. رابط کاربری آن‌ها را از `GET /api/store/contact` دریافت می‌کند. برای تغییر اطلاعات نیازی به ویرایش HTML یا JavaScript نیست.

فایل در هر درخواست خوانده می‌شود؛ پس از ذخیرهٔ JSON معتبر و تازه‌سازی صفحه، تمام محل‌های نمایش به‌روز می‌شوند. در روند استقرار معمول نیز می‌توانید سرور را restart کنید، اما برای تغییر این فایل الزامی نیست. این اطلاعات **عمومی** هستند؛ رمز، توکن، کلید API یا اطلاعات محرمانه را در آن قرار ندهید.

## حالت تحویلی: نمونهٔ ایمن

`mode` برابر `demo` است. در صفحه تماس، بخش جدید صفحه اصلی و فوتر برچسب «اطلاعات آزمایشی» نمایش داده می‌شود.

- شماره‌های تماس و واتساپ از بازهٔ نمایشی رزروشدهٔ `+1 … 555-0100` تا `555-0199` انتخاب شده‌اند؛ شمارهٔ یک کسب‌وکار ایرانی یا شخص دیگر نیستند. پیش‌شمارهٔ خارجی عمدی است تا یک شمارهٔ ایرانی ناشناس به‌اشتباه به عنوان نمونه معرفی نشود.
- ایمیل و لینک‌های نمونه از دامنهٔ رزروشدهٔ `.example` استفاده می‌کنند؛ هیچ حساب واقعی شبکه اجتماعی معرفی نشده است.
- نشانی، «شهر نمونه / خیابان نمونه» است و صریحاً غیرواقعی معرفی می‌شود.
- ساعات کاری برنامهٔ نمونه‌اند، نه وعدهٔ پاسخ‌گویی واقعی.
- شماره‌ها و لینک‌های نمونه **href فعال ندارند**. دکمهٔ واتساپ نمونه disabled و دارای توضیح است؛ هیچ تماس، پیام یا بازشدن دامنهٔ جعلی انجام نمی‌شود.
- نقشه مخفی است، چون موقعیت واقعی تأییدشده نداریم.
- صرف تغییر `mode` به `live`، شماره‌های رزروشده و دامنه‌های نمونه را فعال نمی‌کند. باید آن‌ها را جایگزین یا خالی کنید.

## جایگزینی با اطلاعات واقعی

1. در `backend/config/contact.json` اطلاعات تأییدشدهٔ متعلق به فروشگاه را جایگزین کنید.
2. هر فیلد ناموجود را `""` قرار دهید. کارت یا لینک آن حذف می‌شود؛ جای خالی و placeholder نمایش داده نمی‌شود.
3. `mode` را از `demo` به `live` تغییر دهید.
4. فایل را با UTF-8 و JSON معتبر ذخیره و صفحه را refresh کنید. سبد و سفارش‌ها تغییری نمی‌کنند.
5. شماره و مقصد هر لینک را با صاحب فروشگاه بررسی کنید. اعتبارسنجی قالب، مالکیت حساب یا قابلیت دریافت پیام را اثبات نمی‌کند.

| کلید | قالب و رفتار |
|---|---|
| `mode` | فقط `live` لینک‌های غیرنمونه و معتبر را فعال می‌کند؛ هر مقدار دیگر حالت demo است. این کلید **پرداخت آزمایشی فروشگاه را تغییر نمی‌دهد**. |
| `storeName` | نام مورد استفاده در بخش‌های تماس. لوگو و هویت تصویری موجود تغییر نمی‌کنند. |
| `phone` | ترجیحاً `+` و کد کشور و شماره. شمارهٔ داخلی ایران با صفر اولیه و ۱۱ رقم نیز به `+98` تبدیل می‌شود. ارقام فارسی/عربی، فاصله، پرانتز و خط تیره پشتیبانی می‌شوند. |
| `whatsapp` | شماره به همین قالب، نه URL. مقصد خودکار `https://wa.me/` به‌علاوهٔ ارقام بین‌المللی بدون `+` و صفر داخلی است. |
| `address` | متن نشانی کامل تأییدشده؛ رشتهٔ خالی برای مخفی‌سازی. |
| `email` | آدرس ایمیل معتبر. در live لینک `mailto:` با encoding امن ایجاد می‌شود. |
| `workingHours` | متن دلخواه فارسی؛ مثلاً روزها و بازهٔ زمانی واقعی مورد تأیید فروشگاه. |
| `instagram` | URL کامل HTTPS پروفایل روی `instagram.com` یا `www.instagram.com`، بدون query/hash یا credentials. |
| `telegram` | URL کامل HTTPS پروفایل روی `t.me` یا `telegram.me`. |
| `map.verified` | فقط پس از بررسی مختصات واقعی `true` شود. |
| `map.latitude` | عدد از ‎−۹۰ تا ۹۰؛ در نبود اطلاعات `null`. |
| `map.longitude` | عدد از ‎−۱۸۰ تا ۱۸۰؛ در نبود اطلاعات `null`. |

## نقشه و حریم خصوصی

تنها وقتی mode برابر live، verified برابر true و هر دو مختصات عددی معتبر باشند، کارت موقعیت و دکمهٔ بازکردن OpenStreetMap نمایش داده می‌شود. این پیاده‌سازی **لینک نقشه** است، نه iframe یا سرویس geocoding. نشانی به مختصات حدسی تبدیل نمی‌شود و قبل از کلیک، درخواست شخص ثالثی به سرویس نقشه ارسال نمی‌شود. هیچ نقطهٔ نمونه‌ای به عنوان موقعیت فروشگاه تحویل داده نشده است.

## محل‌های نمایش

- صفحهٔ تماس: کارت تماس، واتساپ، ایمیل، نشانی، ساعت کاری و شبکه‌های اجتماعی؛ همان فرم تماس پایدار قبلی.
- صفحهٔ اصلی: بخش کوچک انتهایی با تماس، واتساپ، نشانی، ساعت کاری و لینک صفحه تماس.
- فوتر تمام ۲۱ صفحه: جزئیات و شبکه‌های اجتماعی با چیدمان واکنش‌گرا.
- نوار بالای header در desktop: شمارهٔ واقعی در صورت تنظیم، سپس واتساپ به‌عنوان جایگزین؛ در حالت نمونه فقط میانبر «ارتباط با هشتگ». در موبایل برای جلوگیری از شلوغی همان منوی تماس موجود استفاده می‌شود.

## خطا و امنیت

فیلدهای خالی/نامعتبر مخفی می‌شوند. پروتکل‌های ناامن، دامنه‌های نامرتبط برای شبکه‌های اجتماعی و شماره‌های malformed لینک فعال نمی‌سازند. همه متن‌ها پیش از نمایش escape می‌شوند. تنظیمات خراب، پاسخ 503 محدود می‌دهد و صفحه با لینک تماس/فرم و پیام fallback ادامه می‌دهد؛ سبد خرید و قابلیت‌های دیگر وابسته به موفقیت این endpoint نیستند. درخواست تنظیمات در مرورگر پس از چهار ثانیه timeout می‌شود.

در این به‌روزرسانی ارسال ایمیل، SMS، بات واتساپ یا سرویس جدیدی متصل نشده است. فرم تماس مثل قبل، پیام را در SQLite ذخیره می‌کند و آزمایشی بودن پاسخ‌گویی را توضیح می‌دهد.

## آزمون

`npm test` اعتبارسنجی تنظیمات، قالب tel/wa.me، مخفی‌سازی، جلوگیری از فعال شدن نمونه‌ها، محدودیت نقشه، API تماس و کل آزمون‌های خرید را اجرا می‌کند. `npm run test:ui` علاوه بر مسیر کامل خرید، هر سه محل نمایش را در پنج اندازه بررسی می‌کند. آزمون حالت live از پاسخ mock و شمارهٔ رزروشده استفاده می‌کند و هیچ شماره، لینک بیرونی یا حساب واقعی را فراخوانی نمی‌کند.
