# مهاجرت امن کاتالوگ مرجع

## منبع و خروجی بررسی‌شده

منبع اصلی `database/store.sqlite` صرفاً خوانده شده و حذف/بازنویسی نشده است. inventory و هش‌ها در `CONVERSION-INVENTORY.md`، `source-inventory.json` و `reports/source-preservation.json` موجودند.

| داده | تعداد |
|---|---:|
| محصول | ۲۸ |
| دستهٔ منبع | ۴۷ |
| رابطهٔ محصول/دسته | ۹۱ |
| مقاله | ۳ |
| مسیر رسانهٔ متمایز | ۵۸ |
| برگهٔ موردنیاز | ۱۵ |
| مجموع کارهای مهاجرت | ۹۳ |

دستهٔ پیش‌فرض خود WooCommerce ممکن است جداگانه وجود داشته باشد؛ ۴۷ به معنی دسته‌های **منبع** است، نه حذف دسته‌های قبلی هاست. محصول غیرمرتبط به دسته اضافه نمی‌شود تا همهٔ دسته‌ها ظاهراً پر باشند. دسته‌های والد از فرزندان محصول نشان می‌دهند؛ تعدادی دستهٔ مرجع واقعاً محصول ندارند.

## اجرای پیشخوان

1. پشتیبان، staging، WooCommerce فعال و واحد IRT.
2. Mobile Hashtag ← مهاجرت کاتالوگ. هر مرحله حداکثر ۵ job. ترتیب: دسته‌های والد/فرزند، محصولات، مقالات، برگه‌ها.
3. گزارش پایین صفحه را بررسی کنید: `imported`، `skipped`، `skipped-existing-page` یا `failed` همراه علت. گزارش/offset در options محفوظ است و بستن مرورگر آن را حذف نمی‌کند.
4. تا ۹۳/۹۳ ادامه دهید. وجود `failed` حتی با رسیدن offset به انتها به معنی مهاجرت کامل نیست. علت را اصلاح و «بازآزمایی از ابتدا» اجرا کنید.
5. محصولات، تصاویر شاخص/گالری و دسته‌ها را در پیشخوان بومی کنترل کنید. تنظیم اتصال برگه‌ها را طبق INSTALL-FA انجام دهید.

## حفاظت از دادهٔ موجود

- کلید منبع و علامت تکمیل برای جلوگیری از تکرار ثبت می‌شود. اجرای مجدد محصول تکمیل‌شده را بازنویسی نمی‌کند؛ تغییر نام/قیمت مدیر محفوظ است.
- SKU یا slug متداخل با دادهٔ غیرمهاجرتی باعث توقف همان مورد و ثبت خطا می‌شود، نه استفاده/بازنویسی بی‌اجازهٔ آن.
- برگهٔ دارای slug موجود حفظ می‌شود. در سایت موجود، مدیر باید محتوا/shortcode آن را بازبینی کند.
- محصول تا تکمیل دسته‌ها و رسانه‌ها draft باقی می‌ماند. فایل‌های رسانه بر اساس SHA-256 شناسایی می‌شوند تا دوباره وارد نشوند؛ فایل حذف‌شده از دیسک در retry قابل بازیابی است.
- قفل مهاجرت ۳۰۰ ثانیه‌ای مانع اجرای هم‌زمان معمول می‌شود. پس از قطع ناگهانی، برای انقضای قفل صبر و retry کنید.
- حساب، رمز، سفارش، نشست، آدرس مشتری، پیام خصوصی و review فرضی وارد نمی‌شود. امتیاز/فروش نمونهٔ منبع به عنوان آمار واقعی WooCommerce ثبت نمی‌شود؛ خانه فقط داده‌های بومی واقعی را مبنای نمایش قرار می‌دهد.

## قیمت، ویژگی و رنگ

نام، slug، SKU، شرح/شرح کوتاه، قیمت عادی/فروش ویژه، موجودی، featured، ویژگی‌های مرئی، رنگ، برند، تصاویر و روابط منبع از طریق APIهای WordPress/WooCommerce وارد می‌شوند. همهٔ ۲۸ محصول منبع ساده‌اند؛ رنگ‌ها انتخاب اجباری با موجودی مشترک‌اند و در سبد/سفارش ثبت می‌شوند. variation جعلی تولید نمی‌شود. برای رنگ دارای SKU/قیمت/موجودی مستقل، از محصول متغیر بومی ووکامرس استفاده کنید.

واحد ورودی منبع IRT است. هیچ تبدیل خودکار ×۱۰/÷۱۰ صورت نمی‌گیرد. سفارش/پرداخت جدید باید پس از بررسی قیمت‌ها انجام شود.

## ابزار توسعه و نتیجهٔ واقعی

`tools/export-catalog.py` خروجی allowlist عمومی را از SQLite می‌سازد؛ اجرای آن برای نصب عادی لازم نیست. `plugin/mobile-hashtag-core/data/catalog.json` و `data/media/` داخل افزونه موجودند.

آزمون `tests/migration.php` روی WooCommerce رسمی ساخته‌شده از تگ 11.2.2: ۱۱ موفق؛ شامل شمارش ۲۸/۴۷/۹۱، قیمت/SKU/slug/stock/شرح، تصویر/گالری، hierarchy، ۳ مقاله، retry بدون افزایش ۵۸ رسانه، حفظ ویرایش مدیر و رد واحد ناسازگار. فایل خام: `reports/migration-test.txt`. نتیجه مربوط به PHP-WASM/SQLite Integration است؛ تست هاست MySQL/MariaDB جداگانه لازم است.
