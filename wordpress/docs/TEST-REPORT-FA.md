# گزارش تست — موبایل هشتگ ۱.۰.۶

تاریخ اجرا: **۱۴ نوامبر ۲۰۲۶** · شاخه: `arena/ad4d2c4e-mobilehashtag` · کامیت مبنا: `9316a56`

> این گزارش فقط چیزهایی را می‌گوید که **واقعاً اجرا شده‌اند**. بخش ۶ فهرست صریح کارهایی است که انجام **نشده‌اند**. هیچ تستی به‌عنوان «پاس» ثبت نشده مگر خروجی واقعی داشته باشد.

### آنچه این یعنی
این محیط، **وردپرس و ووکامرس واقعی** است: هستهٔ رسمی، دیتابیس واقعی، سفارش واقعی، سبد واقعی. ولی **جای هاست ادمین با MySQL را نمی‌گیرد**. دو تفاوت مهم:

1. **SQLite ≠ MySQL.** چند کوئری ووکامرس که مخصوص MySQL نوشته شده‌اند روی SQLite رفتار متفاوت دارند. یکی از این‌ها در همین تست، ثبت سفارش را کاملاً می‌شکست (بخش ۴).
2. **بدون مرورگر.** همهٔ بررسی‌ها HTTP + تحلیل HTML/text + تست‌های سطح PHP هستند. **هیچ رگرسیون بصری، اسکرین‌شات، یا تست چیدمان پیکسلی انجام نشد.**

## ۲. تست‌های خودکار HTTP — نتیجه: **۱۱۱ از ۱۱۱**

**این ۱۱۱ بررسی روی همان فایل‌هایی اجرا شد که در دو ZIP نهایی هستند** (ZIPها استخراج و جای قالب/افزونه مستقر شدند، سپس تست اجرا شد) — نه روی نسخهٔ توسعه.

ابزار: `wordpress/tools/qa-http.py` — یک مجموعهٔ E2E که با **جلسهٔ کوکی واقعی** کار می‌کند، HTML واقعی را می‌خواند، فرم‌ها را از مارک‌آپ استخراج می‌کند و همان‌ها را POST می‌کند. هیچ داده‌ای mock نشده است.

اجرا:
```
cd wordpress/tools && PYTHONPATH=/tmp/reqs python3 qa-http.py
```

## ۵. تست‌هایی که **پاس نشدند** یا **انجام نشدند**

### ۵.۱ انجام‌نشده — مرورگر و تفاوت بصری
هیچ مرورگری در این محیط قابل اجرا نبود (Chromium به `libnss3 ≥ NSS_3.30` نیاز دارد و در دسترس نبود). بنابراین:

- ❌ اسکرین‌شات یا diff بصری پیکسل‌به‌پیکسل با منبع
- ❌ تست چیدمان در عرض‌های موبایل/تبلت/دسکتاپ
- ❌ تست تعاملی اسلایدر، منوی موبایل، دیالوگ سریع، quick-view با کلیک واقعی
- ❌ تست جاوااسکریپت سمت مرورگر (فقط وجود مارک‌آپ و فایل بررسی شد)

**پس ادعای «پیکسل-دقیق» تأیید نشده است.** آنچه تأیید شد: ساختار HTML، کلاس‌ها، متن فارسی، وجود همهٔ بخش‌ها و بارگذاری همهٔ تصاویر.

### ۵.۲ انجام‌نشده — MySQL/MariaDB
کل تست روی SQLite اجرا شد. به‌طور خاص تأیید نشده:
- ❌ کوئری‌های Action Scheduler و صف کارهای پس‌زمینه
- ❌ رفتار `FOR UPDATE` و قفل ردیف واقعی
- ❌ مهاجرت HPOS روی MySQL واقعی
- ❌ ارتقای نسخهٔ ووکامرس روی دیتابیس زنده

### ۵.۳ انجام‌نشده — ایمیل و پرداخت
- ❌ **ارسال ایمیل واقعی**: SMTP تنظیم نبود. همهٔ پیام‌ها با `mail_status=disabled` ذخیره شدند. ذخیرهٔ DB تأیید شد، تحویل ایمیل نه.
- ❌ **پرداخت بانکی واقعی**: هیچ درگاهی نصب نیست و هیچ تراکنشی انجام نشد. سفارش‌ها با COD ثبت شدند.

### ۵.۴ محدودیت‌های شناخته‌شده
- `wp-content/debug.log` پاک نبود؛ رکوردهای قدیمی (از جمله ۳ fatal قبلی که رفع شدند) تا زمان پاک‌سازی وجود دارند. پس از پاک‌سازی و پیمایش کامل، **صفر** خطای تازه ثبت شد.
- محصولات تست شده در هر اجرا موجودی واقعی کم می‌کنند (سفارش‌های ۱۵۰ به بعد). این رفتار صحیح ووکامرس است، نه عیب.
- یک دستهٔ تکراری-نام در منبع وجود دارد (بخش ۳).

## ۶. بازتولید تست‌ها

```bash
# ۱) محیط QA (PHP-WASM + SQLite + وردپرس + ووکامرس)
cd /home/user/mobilehashtag/wordpress/tools
node qa-server.mjs                 # http://localhost:9500

# ۲) مجموعهٔ E2E — ۱۱۱ بررسی
cd wordpress/tools
PYTHONPATH=/tmp/reqs python3 qa_http.py   # فایل: qa-http.py

# ۳) لینت PHP روی قالب و افزونهٔ مستقرشده
node qa-server.mjs --run /tmp/qa/lint3.php
# انتظار: LINTED=33 SYNTAX_ERRORS=0

# ۴) تست idempotent بودن ایمپورت
node qa-server.mjs --run /tmp/qa/idem.php
# انتظار: identical=true / failed=0
```

> ابزارهای QA (`qa-http.py`، `qa-server.mjs`، `php-run.mjs`) **داخل ZIPها نیستند** — فقط ابزار توسعه‌اند.

**۴۷ یا ۴۸ دسته؟** کاتالوگ ۴۷ دسته دارد. دستهٔ چهل‌وهشتم دستهٔ پیش‌فرض خود ووکامرس (`uncategorized` / «دسته‌بندی نشده») است که در نصب ساخته می‌شود و جزو کاتالوگ نیست.

> **محدودیت:** در این محیط، پیام خطای فرم پیگیری سفارش در تست HTTP دستی من دیده نمی‌شد، چون `home_url()` روی https تنظیم شده و کوکی `secure` است ولی درخواست‌های من روی http بود؛ مجموعهٔ رسمی `qa-http.py` که همان مسیر را می‌پیماید **۱۱۱/۱۱۱** پاس می‌شود. این رفتار روی هاست واقعی https مشکلی ندارد اما روی نصب http خالص، پیگیری سفارش برای مهمان وابسته به کوکی است.

---

## ۷. جمع‌بندی صادقانه

**تأییدشده با اجرای واقعی:** کاتالوگ واقعی در دیتابیس، سبد خرید واقعی، تسویه‌حساب واقعی، سفارش واقعی، ثبت‌نام واقعی، ذخیرهٔ واقعی پیام، پیگیری از سفارش واقعی، مدیریت کامل پیشخوان، صفر خطای PHP، صفر خطای نحوی.

**تأیید‌نشده:** ظاهر پیکسلی در مرورگر، رفتار روی MySQL، تحویل ایمیل، پرداخت بانکی.

برای فروش واقعی، پیش از انتشار: روی یک هاست با **MySQL/MariaDB** نصب کنید، یک سفارش واقعی با درگاه تست بزنید، و ظاهر را در مرورگر واقعی روی موبایل و دسکتاپ ببینید.
