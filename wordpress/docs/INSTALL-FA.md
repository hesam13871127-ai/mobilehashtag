# نصب و اصلاح فروشگاه MOBILE HASHTAG — نسخهٔ 1.0.2

این نسخه قالب WordPress و افزونهٔ مستقل Core است؛ راهنمای قدیمی Node/Windows برای آن کاربرد ندارد. **هاست مشتری به Node، Arena، PHP-WASM، SQLite یا mount نیاز ندارد.**

## ۱. پیش‌نیاز و نصب

1. از فایل‌ها و دیتابیس پشتیبان بگیرید؛ ابتدا staging. WordPress رسمی، PHP حداقل 8.1 و MySQL/MariaDB مطابق نیاز نسخهٔ WooCommerce نصب‌شده لازم‌اند. حداقل حافظهٔ پیشنهادی 256MB و محدودیت آپلود بیشتر از ۱۶MB برای قالب در نظر بگیرید.
2. **WooCommerce رسمی را جداگانه** از افزونه‌ها ← افزودن نصب و فعال کنید. نسخهٔ آزموده‌شده 11.2.2 است؛ حداقل WordPress اعلام‌شده برای خود بسته‌های هشتگ 6.5 است، ولی الزامات نسخهٔ WooCommerce هم باید رعایت شود.
3. از افزونه‌ها ← افزودن ← بارگذاری، `mobile-hashtag-core-plugin.zip` را نصب و فعال کنید.
4. از نمایش ← پوسته‌ها ← افزودن ← بارگذاری، `mobile-hashtag-wordpress-theme.zip` را نصب و فعال کنید.
5. برای ارتقا از 1.0.1 همین دو ZIP را بارگذاری و جایگزینی نسخه را تأیید کنید. پوشهٔ سایت، دیتابیس یا WooCommerce را حذف نکنید. Core پیام‌ها/تنظیمات موجود را حذف نمی‌کند.
6. زبان سایت فارسی و منطقهٔ زمانی مناسب (مثلاً Asia/Tehran) را انتخاب و ترجمه‌های رسمی WordPress/WooCommerce را به‌روز کنید. HTTPS و پیوندهای یکتای استاندارد وردپرس لازم‌اند.

## ۲. قدم ضروری: راه‌اندازی فروشگاه و محصولات

بعد از فعال‌سازی، وارد پیشخوان شوید. منوی **Mobile Hashtag ← راه‌اندازی فروشگاه** و اعلان بالای پیشخوان را خواهید دید. برگه‌های ضروری، مستقل از محصولات، در اولین بازدید مدیریتی با قالب فعال ساخته می‌شوند؛ تنظیمات خالی/نامعتبر صفحات نیز متصل می‌شوند.

برای ورود کاتالوگ:

1. اگر فروشگاه **کاملاً خالی** است و واحد آن تومان نیست، گزینهٔ «در فروشگاه کاملاً خالی، واحد پول را تومان قرار بده» را انتخاب کنید. این اجازه روی فروشگاه دارای محصول یا سفارش اعمال نمی‌شود؛ تغییر واحد قیمت‌های قبلی را تبدیل نمی‌کند.
2. گزینهٔ **اتصال برگه‌های هشتگ و تبدیل بلوک رسمی سبد/تسویه** را انتخاب کنید تا صفحهٔ نخست، وبلاگ، فروشگاه، سبد، تسویه، حساب، قوانین و حریم خصوصی به صفحات صحیح متصل شوند. اگر Cart/Checkout قبلی دارای بلوک رسمی باشند، فقط همان بلوک‌ها به shortcode رسمی تبدیل می‌شوند؛ سایر متن‌ها و بلوک‌ها حفظ می‌شوند. اصل محتوا در meta خصوصی `_mhc_classic_backup_102` و بازبینی‌های استاندارد وردپرس نگهداری می‌شود. این تغییر فقط با تأیید همین گزینه انجام می‌شود.
3. **«راه‌اندازی کامل / ادامهٔ ورود محصولات»** را بزنید. تا پایان، صفحه را باز نگه دارید. درخواست‌های کوچک به‌صورت خودکار اجرا می‌شوند؛ لازم نیست دکمه را ده‌ها بار بزنید.
4. پایان موفق باید بدون خطا باشد. **۲۸ محصول واقعی، ۴۷ دستهٔ منبع و ۳ مقاله** وارد می‌شود. موارد موجود و کامل رد می‌شوند؛ گزارش تعداد imported/skipped/failed و علت هر شکست دیده می‌شود.
5. محصولات ← همه محصولات و صفحهٔ فروشگاه را باز کنید. قیمت‌ها و موجودی نمونه را پیش از فروش واقعی بازبینی کنید.

**محصولات با صرف کپی ZIP و بدون تأیید ورود کاتالوگ به فروشگاه واقعی اضافه نمی‌شوند.** این تأیید یک‌باره برای جلوگیری از آلوده‌کردن کاتالوگ فروشگاه فعال است؛ اعلان و دکمهٔ مشخص برای آن وجود دارد. برگه‌ها به این تأیید یا واحد تومان وابسته نیستند.

اگر اینترنت/مرورگر قطع شد، همان صفحه را باز و «ادامه» را بزنید. پس از رفع خطا، «بازآزمایی از ابتدا» را بزنید؛ محصول/دسته/تصویر تکراری ساخته نمی‌شود. جزئیات: [MIGRATION-FA.md](MIGRATION-FA.md).

## ۳. صفحات و منوها

[فهرست کامل صفحات](PAGES-FA.md). مسیرهای اصلی نصب تازه:

`/`، `/shop/`، `/about/`، `/contact/`، `/tracking/`، `/my-account/`، `/cart/`، `/checkout/`، `/terms/`، `/privacy/`، `/blog/`.

- منوهای اصلی و دو بخش پابرگ، اگر جایگاه آنها خالی باشد، ساخته و متصل می‌شوند. از **نمایش ← فهرست‌ها** ویرایش کنید. منوی اختصاصی قبلی جایگزین نمی‌شود؛ لینک سفارشی قدیمی آن را به برگهٔ واقعی تبدیل کنید.
- محتوای درباره/تماس/قوانین/حریم خصوصی از **برگه‌ها** ویرایش می‌شود. صفحهٔ تماس از `[mh_contact_details]` و `[mh_contact_form]` استفاده می‌کند.
- اگر یک برگهٔ همنام قبلی وجود دارد، محتوا حفظ می‌شود. برگهٔ پیش‌نویس قبلی را مدیر باید منتشر کند؛ خطای این وضعیت در گزارش دیده می‌شود. تنها تبدیل اختیاری بلوک‌های تجارت مطابق توضیح بالا استثناست.
- برای احراز اتصال‌ها: تنظیمات ← خواندن و WooCommerce ← پیکربندی ← پیشرفته. پیوندهای یکتا هنگام راه‌اندازی تازه‌سازی می‌شوند؛ تغییر مسیرهای سرور کار افزونه نیست. اگر *همهٔ* مسیرهای زیبا 404 هستند، تنظیمات ← پیوندهای یکتا ← ذخیره؛ دسترسی `.htaccess` روی Apache یا `try_files $uri $uri/ /index.php?$args;` در پیکربندی معمول Nginx باید توسط مدیر هاست صحیح باشد.

## ۴. ظاهر و اطلاعات تماس

- نمایش ← سفارشی‌سازی: لوگو، رنگ طلایی، اعلان، بنر/تصویر/لینک، عنوان و نمایش بخش‌های خانه، پابرگ.
- Mobile Hashtag ← Store Settings: نام کسب‌وکار، تلفن، ایمیل عمومی، نشانی، ساعت، شبکه‌های اجتماعی و گیرندهٔ اعلان مدیر.
- پیش‌فرض‌ها **نمونه و غیرواقعی** و لینک تماس آنها غیرفعال است. پس از ورود اطلاعات واقعی، حالت واقعی را فعال کنید. هیچ نشانی تأییدشده یا نقشهٔ ساختگی ادعا نشده است.
- فرم تماس: نام، تلفن/ایمیل، موضوع، پیام و رضایت. پیام قبل از ارسال ایمیل در دیتابیس ذخیره می‌شود. در صفحهٔ تماس، بخش بازشوندهٔ «درخواست پیش‌خرید یا مشاورهٔ محصول» از همان ذخیره‌ساز مستقل با نوع inquiry استفاده می‌کند. همچنین `[mh_contact_form type="inquiry"]` در هر برگه قابل استفاده است.
- پیام‌ها از Mobile Hashtag ← پیام‌ها و خبرنامه با جزئیات، تاریخ/ساعت محلی سایت، وضعیت، جست‌وجو، CSV و حذف تأییدشده مدیریت می‌شوند.

## ۵. پیش از فروش عمومی

روش ارسال، مالیات، موجودی، ثبت‌نام حساب، سیاست حقوقی، درگاه و گیرندهٔ ایمیل را مطابق کسب‌وکار تنظیم کنید. پرداخت COD در staging امکان آزمون سفارش واقعی WooCommerce بدون درگاه بانکی را می‌دهد. **تحویل SMTP و پرداخت بانکی واقعی در این پروژه تأیید نشده‌اند.**

صفحات سبد/تسویه/حساب و HTML دارای nonce/علاقه‌مندی شخصی را از full-page-cache مشترک CDN خارج کنید. Core هدرهای no-cache می‌فرستد، ولی CDN باید آنها را رعایت کند. cache فایل‌های ثابت مجاز است.

آزمون‌ها روی WordPress واقعی در PHP-WASM/SQLite اجرا شده‌اند؛ **آزمون بومی MySQL/MariaDB انجام نشده**. این ابزارها فقط محیط توسعه‌اند، نه نیاز بسته‌ها. قبل از فروش، یک سفارش کنترل‌شده و ارسال ایمیل روی staging هاست واقعی انجام دهید. [QA نهایی](FINAL-QA-FA.md) و [محدودیت‌ها](KNOWN-LIMITATIONS.md) را بخوانید.

## حفظ و حذف داده

تغییر پوسته یا غیرفعال‌کردن Core، محصول/سفارش/پیام‌های موجود را پاک نمی‌کند. محصولات و سفارش‌ها متعلق به WooCommerce هستند. حذف پیام‌ها فقط با عملیات مجاز پیشخوان و تأیید انجام می‌شود. پیش از هر ارتقا یا مهاجرت، پشتیبان مستقل داشته باشید.
