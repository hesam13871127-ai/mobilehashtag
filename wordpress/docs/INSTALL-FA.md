# راهنمای نصب موبایل هشتگ — نسخهٔ 1.0.1

این راهنما مربوط به **قالب WordPress + افزونهٔ Core** است؛ راهنمای تاریخی Node/Windows برای این نسخه کاربرد ندارد. هیچ Node، SQLite منبع یا Express API روی هاست فروشگاه لازم نیست.

## پیش از نصب

1. روی staging و با پشتیبان کامل فایل/دیتابیس شروع کنید. ابتدا روی سایت دارای مشتری/سفارش واقعی مهاجرت نکنید.
2. هاست HTTPS، PHP حداقل 8.1 (ترجیحاً نسخهٔ مورد پشتیبانی WooCommerce نصب‌شده)، افزونه‌های موردنیاز خود WordPress/WooCommerce، دسترسی نوشتن uploads و حداقل 256MB حافظه فراهم کنید. محدودیت آپلود باید از حجم ZIP قالب بیشتر باشد.
3. WordPress رسمی (حداقل 6.5) و افزونهٔ رسمی **WooCommerce** را جداگانه نصب کنید. نسخهٔ بررسی‌شدهٔ WooCommerce در این پروژه **11.2.2** است؛ برای نسخه‌های جدیدتر ابتدا روی staging آزمایش کنید. هیچ نسخه‌ای از آنها در بسته‌های هشتگ نیست؛ افزونهٔ پولی اجباری وجود ندارد. الزامات نسخهٔ WooCommerce را در صفحهٔ رسمی همان نسخه بررسی کنید.
4. تنظیمات ← همگانی: زبان فارسی، منطقهٔ زمانی Asia/Tehran، نشانی صحیح HTTPS. پیشخوان ← به‌روزرسانی‌ها: ترجمه‌ها را به‌روز کنید. بسته‌های فارسی WordPress و WooCommerce برای رشته‌های بومی آنها لازم‌اند؛ قالب جایگزین فایل زبان هسته نیست.

## نصب دو فایل

1. افزونه‌ها ← افزودن افزونه ← بارگذاری: `mobile-hashtag-core-plugin.zip`، نصب و فعال‌سازی.
2. نمایش ← پوسته‌ها ← افزودن ← بارگذاری: `mobile-hashtag-wordpress-theme.zip`، نصب و فعال‌سازی.
3. ریشهٔ ZIP افزونه فقط `mobile-hashtag-core/` و ریشهٔ ZIP پوسته فقط `mobile-hashtag/` است. ZIP کل مخزن، پوشهٔ `wordpress` یا فایل‌های توسعه را بارگذاری نکنید.
4. اگر ووکامرس هنوز فعال نیست، پیام آماده‌سازی فروشگاه طبیعی است؛ فرم‌ها و داده‌های Core همچنان مستقل‌اند.

## تنظیم اطلاعات واقعی

**Mobile Hashtag ← Store Settings**: نام، تلفن، واتساپ، ایمیل عمومی، ساعات، نشانی، شبکه‌های اجتماعی و گیرندهٔ اعلان مدیر را وارد کنید. پیش‌فرض‌ها کاملاً فرضی، دارای برچسب نمونه و فاقد لینک تماس فعال‌اند. فقط پس از جایگزینی و تأیید همهٔ اطلاعات، حالت «واقعی» را انتخاب کنید. گیرندهٔ اعلان با ایمیل عمومی متفاوت است؛ بدون گیرندهٔ واقعی اعلان ارسال نمی‌شود، اما پیام ذخیره می‌شود. نقشهٔ ساختگی یا مکان تأییدنشده وجود ندارد.

## قیمت و کاتالوگ

- ووکامرس ← پیکربندی ← همگانی: واحد **تومان ایران / IRT** برای ورود کاتالوگ مرجع. پیشنهاد نمایش: بدون اعشار، جداکنندهٔ هزارگان و واحد کنار رقم.
- عدد ورودی همان عدد محصول، سبد، سفارش و ایمیل است. تغییر واحد ارقام را ضرب/تقسیم نمی‌کند. برای استفاده از ریال، پیش از ثبت محصولات جدید واحد IRR انتخاب کنید؛ مهاجرت کاتالوگ تومانی در IRR عمداً متوقف می‌شود. [جزئیات](WOOCOMMERCE-FA.md).
- Mobile Hashtag ← مهاجرت کاتالوگ: هر بار «مرحلهٔ بعدی»؛ تا ۹۳ از ۹۳ ادامه دهید و گزارش خطا را بررسی کنید. [راهنمای مهاجرت](MIGRATION-FA.md).

## اتصال صفحات (عمداً به انتخاب مدیر)

ابزار مهاجرت تنظیمات صفحهٔ اصلی یا صفحات تجارت سایت موجود را بازنویسی نمی‌کند:

| تنظیم | برگه |
|---|---|
| تنظیمات ← خواندن ← صفحهٔ نخست ایستا | خانه (`home`) |
| همان صفحه ← برگهٔ نوشته‌ها | مجله هشتگ (`blog`) |
| ووکامرس ← محصولات ← برگه فروشگاه | فروشگاه (`shop`) |
| ووکامرس ← پیشرفته ← سبد خرید | سبد خرید (`cart`) |
| همان صفحه ← تسویه حساب | تکمیل سفارش (`checkout`) |
| همان صفحه ← حساب کاربری | حساب کاربری (`account`) |
| همان صفحه ← شرایط و ضوابط | شرایط خرید و بازگشت (`terms`) |
| تنظیمات ← حریم خصوصی | حریم خصوصی (`privacy`) |

برای چیدمان تأییدشدهٔ سبد/تسویه/حساب، برگه‌ها باید shortcodeهای رسمی زیر را داشته باشند: `[woocommerce_cart]`، `[woocommerce_checkout]` و `[woocommerce_my_account]`. اگر WooCommerce قبلاً برگه‌های بلوکی یا برگه‌های همنام ساخته، واردکننده عمداً محتوای آنها را تغییر نمی‌دهد. در این حالت از «برگه‌ها ← افزودن» سه برگهٔ تازه با عنوان فارسی بسازید، بلوک «کد کوتاه / Shortcode» متناظر را در هرکدام قرار دهید و در تنظیمات پیشرفتهٔ WooCommerce همین سه برگه را انتخاب کنید. نیازی به PHP یا ابزار توسعه نیست؛ برگه‌های قدیمی را بدون بررسی حذف نکنید. بلوک‌های Cart/Checkout رسمی قابل استفاده‌اند، اما تطابق بصری و آزمون این بسته بر پایهٔ shortcode کلاسیک است. تنظیمات ← پیوندهای یکتا را یک‌بار ذخیره کنید. مسیرهای قدیمی `.html` به مقصد وردپرسی مرتبط هدایت می‌شوند؛ سفارش قدیمی به حساب کاربری می‌رود، نه شناسهٔ سفارش قابل جعل.

## مدیریت ظاهر بدون کدنویسی

نمایش ← سفارشی‌سازی:

- هویت سایت: لوگو و نماد سایت؛ بدون انتخاب لوگو، نشان محلی اصلی نمایش داده می‌شود.
- تنظیمات هشتگ: رنگ طلایی، اعلان‌ها، نوشته‌های پابرگ، اسلایدهای اصلی، تصاویر/لینک بنرها، عنوان‌ها و نمایش/عدم نمایش بخش‌های خانه.
- نمایش ← فهرست‌ها: جایگاه‌های منوی اصلی، دسترسی سریع پابرگ و راهنمای مشتری. تا انتخاب فهرست، منوی مرجع نمایش داده می‌شود.
- برگه‌ها/نوشته‌ها: متن درباره، تماس، FAQ، قوانین و مقالات را از ویرایشگر وردپرس تغییر دهید. اطلاعات تماس مرکزی را در متن برگه‌ها تکرار نکنید؛ از `[mh_contact_details]` استفاده کنید.
- محصولات/دسته‌ها/رسانه‌ها: مدیریت کاملاً بومی WooCommerce/WordPress است. رنگ‌های منبع موجودی مشترک دارند؛ برای موجودی مستقل رنگ، محصول متغیر واقعی بسازید.

## پیش از فروش واقعی

- سیاست ارسال/بازگشت، ادعاهای بنرها، حد نصاب ارسال رایگان و متن‌های حقوقی نمونه را با کسب‌وکار واقعی تطبیق دهید. وعده‌های تصویری به‌تنهایی تنظیم ارسال نیستند.
- مناطق و روش‌های ارسال، مالیات، حساب‌ها، موجودی، ایمیل و روش پرداخت را در WooCommerce تنظیم کنید؛ قالب آنها را تحمیل نمی‌کند.
- برای تست، پرداخت هنگام دریافت یا انتقال بانکی مجاز است. این پروژه اتصال/تأیید درگاه بانکی یا پرداخت واقعی را ادعا نمی‌کند.
- SMTP و دریافت واقعی ایمیل را آزمایش کنید؛ [راهنمای پیام‌ها و ایمیل](CONTACT-SMTP-FA.md).
- صفحات شخصی/سبد/تسویه و HTML دارای nonce مهمان را از full-page-cache مشترک CDN خارج کنید. Core هدر no-cache و `DONOTCACHEPAGE` می‌فرستد؛ CDN باید آنها را رعایت کند. cache فایل‌های ثابت مجاز است.
- HTTPS، پشتیبان روزانه، به‌روزرسانی هسته/افزونه‌ها، حساب مدیر با رمز یکتا و آزمایش روی هاست اصلی مسئولیت راه‌اندازی هستند.

## حذف، تعویض و بازیابی

تعویض پوسته دادهٔ Core را حذف نمی‌کند. حذف افزونه نیز uninstall مخرب ندارد؛ پیام‌ها، تنظیمات و علاقه‌مندی حساب باقی می‌مانند. WooCommerce مالک محصولات/سفارش‌هاست. برای پاک‌سازی دادهٔ شخصی از ابزارهای تأیید ایمیل وردپرس یا مدیریت پیام‌ها استفاده کنید؛ حذف کامل جدول فقط با تصمیم مدیر و پشتیبان انجام شود.
