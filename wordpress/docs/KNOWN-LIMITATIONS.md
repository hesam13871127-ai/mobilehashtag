# محدودیت‌ها و الزامات راه‌اندازی — 1.0.1

دو بستهٔ قالب و Core نصب‌شدنی‌اند و به Arena، Node.js، PHP-WASM، SQLite یا virtual mount وابسته نیستند. WooCommerce رسمی باید جداگانه نصب شود. جزئیات آزمون در FINAL-QA-FA.md آمده است.

## مرز آزمون

- آزمون روی WordPress واقعی 7.1.4، PHP 8.3.36 در PHP-WASM و WooCommerce رسمی 11.2.2 ساخته‌شده از تگ رسمی انجام شد. در این محیط PHP-FPM و MySQL/MariaDB در دسترس نبودند و دریافت بسته‌های سیستم از شبکه مسدود شد؛ اجرای بومی روی هاست MySQL/MariaDB **تأیید نشده است**. کد نصب‌شدنی از APIهای استاندارد WordPress/WooCommerce و `$wpdb` استفاده می‌کند، نه SQLite.
- SQLite محیط تست با برخی queryهای Action Scheduler و رزرو موقت موجودی ناسازگار است. سفارش COD با تنظیم رسمی hold-stock=0 فقط در دیتابیس آزمایش انجام شد؛ مدیریت موجودی محصول فعال بود. رزرو هم‌زمان، race condition، cron، analytics و بار بالا روی MySQL باید در staging هاست بررسی شوند. بسته‌ها این تنظیم آزمایشی را روی سایت مشتری اعمال نمی‌کنند.
- پرداخت واقعی، درگاه بانکی، callback بانکی، تحویل واقعی SMTP، ایمیل سفارش و بازیابی رمز از صندوق ایمیل آزمایش نشده‌اند. پذیرفته‌شدن توسط wp_mail اثبات تحویل نیست.
- قالب/Core فارسی و RTL هستند. رشته‌های هستهٔ WordPress/WooCommerce نیازمند بستهٔ زبان رسمی فارسی‌اند. runtime به دلیل محدودیت دریافت language pack از MO قدیمی صرفاً برای آزمایش استفاده کرد؛ آن فایل در ZIPها نیست. پوشش ترجمهٔ تمام رشته‌های جدید WC در runtime ادعا نمی‌شود.
- مرورگر آزمون Chromium headless بود. دستگاه فیزیکی، Safari/Firefox، ممیزی کامل accessibility/نفوذ و همهٔ ترکیب‌های افزونه/نسخه تأیید نشده‌اند.

## انتخاب‌های عمدی محصول

- برای حفظ مرجع تأییدشده، ۲۸ محصول و ۴۷ دسته نگه داشته شد، نه تولید صدها محصول یا حذف بی‌دلیل کاتالوگ قبلی. قیمت/موجودی آنها نمونه است و باید پیش از فروش واقعی بازبینی شود. بعضی دسته‌های جزئی مرجع خالی‌اند؛ محصول نامرتبط برای پرکردن آنها ساخته نشده است.
- منبع محصولات ساده با رنگ و موجودی مشترک دارد. variation جعلی ساخته نمی‌شود؛ محصول متغیر واقعی از پیشخوان WooCommerce پشتیبانی و آزموده شده است. حساب، رمز، سفارش یا review فرضی وارد نمی‌شود. بخش نظرات خانه از نظر تأییدشدهٔ واقعی استفاده می‌کند؛ قبل از وجود نظر، کارت‌های راهنمای خرید نمایش داده می‌شود.
- مهاجرت idempotent است و SKU/slug متداخل یا برگهٔ قبلی را بازنویسی نمی‌کند. اگر WooCommerce قبلاً Cart/Checkout بلوکی ساخته، برای تطابق با طرح مرجع، برگه‌های shortcode رسمی جدید بسازید و در تنظیمات WooCommerce انتخاب کنید؛ راهنما دقیقاً توضیح می‌دهد. بلوک‌های Cart/Checkout سبک بصری متفاوت خود WooCommerce را دارند.
- تغییر IRT/IRR رقم قیمت را تبدیل نمی‌کند؛ ارقام و سازگاری درگاه باید توسط مالک بازبینی شوند. سفارش گذشته واحد خودش را حفظ می‌کند.
- خبرنامه ثبت درخواست/رضایت و مدیریت آن است؛ سرویس ارسال کمپین، double opt-in یا لغو عضویت ایمیلی خودکار نیست.
- علاقه‌مندی مهمان transient حداکثر ۳۰روزه است؛ پاک‌کردن cookie/transient ممکن است آن را زودتر حذف کند. علاقه‌مندی حساب در user meta پایدار است.
- HTML دارای nonce/علاقه‌مندی شخصی نباید full-page-cache مشترک شود. Core هدر no-cache و DONOTCACHEPAGE را اعلام می‌کند؛ CDN باید آن را رعایت کند.
- اطلاعات تماس پیش‌فرض صریحاً فرضی و لینک‌هایش غیرفعال است. مالک باید اطلاعات واقعی، سیاست حقوقی، وعده‌های تبلیغاتی، ارسال/مالیات و پرداخت را تنظیم کند. نقشهٔ ساختگی وجود ندارد.
- دادهٔ پیام‌ها خودکار در دورهٔ زمانی مشخص حذف نمی‌شود؛ مالک سیاست نگهداری و حذف دوره‌ای را تعیین کند. uninstall مخرب وجود ندارد تا حذف افزونه باعث ازبین‌رفتن پیام‌ها نشود.
