# تماس با ما، پیام‌ها، خبرنامه و SMTP

نسخه: **۱.۰.۶** · فرم‌ها: `[mh_contact_form]`، `[mh_contact_form type="inquiry"]`، `[mh_newsletter]`، `[mh_contact_details]`

---

## ۱. مسیر داده (مهم‌ترین قاعده)

```
فرم  →  nonce (mhc_submit_<type>)  →  honeypot + رضایت + اعتبارسنجی سمت سرور
     →  درج واقعی در جدول wp_mh_submissions
     →  تلاش جداگانه برای ایمیل (اختیاری)
     →  پاسخ «ذخیره شد» با UUID
```

**ذخیره در دیتابیس هرگز به SMTP وابسته نیست.** پیام اول در دیتابیس ثبت می‌شود و بعد ایمیل تلاش می‌شود؛ شکست ایمیل هیچ رکوردی را حذف نمی‌کند و موفقیت جعلی هم نمی‌سازد. پیام موفقیت فقط پس از `$wpdb->insert()` واقعی نمایش داده می‌شود — هیچ پارامتر URL یا پاسخ JavaScript موفقیت ساختگی ایجاد نمی‌کند.

پیام موفقیت خودش صریح می‌گوید: «این تأیید صرفاً ذخیرهٔ پیام است؛ تحویل ایمیل تأیید نشده است.»

---

## ۲. جدول `wp_mh_submissions`

| ستون | توضیح |
|---|---|
| `id` | شمارهٔ داخلی |
| `uuid` | شناسهٔ عمومی (نمایش به کاربر) |
| `created_at` | زمان UTC |
| `type` | `contact` / `inquiry` / `newsletter` |
| `status` | `new` / `contacted` / `completed` |
| `name`, `phone`, `email` | نام، تلفن، ایمیل (ایمیل در تماس اختیاری است) |
| `message` | متن پیام |
| `source_url` | آدرس مبدأ، **بدون query** (کلید سفارش/حساب ذخیره نمی‌شود) |
| `fields` | JSON فیلدهای مجاز و رضایت |
| `mail_status` | `pending` / `accepted` / `failed` / `disabled` |
| `mail_error` | متن خطای واقعی wp_mail |

`accepted` به معنی **پذیرش برای ارسال** است، نه تحویل. تحویل را فقط لاگ SMTP یا صندوق گیرنده تأیید می‌کند.

**IP خام ذخیره نمی‌شود.** برای محدودیت نرخ فقط یک هش HMAC از IP استفاده می‌شود.

## ۳. محافظت ضد اسپم

| لایه | توضیح |
|---|---|
| nonce | `mhc_nonce` مخصوص هر نوع فرم؛ عدم تطابق → ۴۰۳ |
| Honeypot | فیلد `website` پنهان؛ پر شدنش → ۴۲۲ و عدم ذخیره |
| رضایت صریح | `consent=1` اجباری |
| محدودیت طول | نام ۲–۱۰۰، پیام ۱۰–۵۰۰۰، موضوع ≤۱۶۰، ایمیل ≤۲۵۴ |
| محدودیت نرخ | ۱۲ ارسال در ساعت برای هر IP (قابل تغییر با فیلتر `mhc_submission_hourly_limit`) → ۴۲۹ |

این‌ها دفاع پایه هستند و جای سرویس مقابله با حملهٔ توزیع‌شده را نمی‌گیرند. پشت پراکسی/CDN، هاست باید `REMOTE_ADDR` را امن تنظیم کند؛ به هدر `X-Forwarded-For` ارسالی کاربر اعتماد نکنید.

## ۴. تنظیم گیرنده و SMTP

1. **موبایل هشتگ ← تنظیمات فروشگاه** ← ایمیل گیرنده را وارد کنید.
2. تا وقتی ایمیل گیرنده یک آدرس واقعی نباشد، `mail_status` روی **`disabled`** می‌ماند و پیام‌ها فقط ذخیره می‌شوند. این رفتار عمدی است: بدون SMTP هیچ چیز نمی‌شکند.
3. برای ارسال واقعی ایمیل، یک افزونهٔ SMTP معتبر نصب کنید (مثلاً WP Mail SMTP) و با سرویس واقعی تنظیمش کنید. افزونهٔ هشتگ هیچ ایمیل‌فرست اختصاصی ندارد و از `wp_mail()` استاندارد استفاده می‌کند؛ بنابراین با هر افزونهٔ SMTP سازگار است.
4. پس از تنظیم SMTP، یک پیام آزمایشی بفرستید و ستون `mail_status` را در **موبایل هشتگ ← پیام‌ها و خبرنامه** بررسی کنید: `accepted` یعنی برای ارسال پذیرفته شد، `failed` یعنی متن خطا در `mail_error` ذخیره شده است.

> در تست‌های این پروژه **SMTP تنظیم نبود** و بنابراین **هیچ ایمیلی ارسال نشد**. آنچه تأیید شد، ذخیرهٔ واقعی پیام‌ها در دیتابیس بود (`mail_status = disabled` با دلیل «گیرندهٔ واقعی تنظیم نشده است»).

## ۵. مدیریت پیام‌ها در پیشخوان

**موبایل هشتگ ← پیام‌ها و خبرنامه**

- فهرست با صفحه‌بندی ۲۵تایی
- جست‌وجو در متن/نام/ایمیل/شناسه
- فیلتر نوع (`contact`/`inquiry`/`newsletter`)، وضعیت (`new`/`contacted`/`completed`) و بازهٔ تاریخ
- مشاهدهٔ کامل هر پیام + همهٔ فیلدهای JSON
- تغییر وضعیت (جدید/تماس گرفته شد/تکمیل‌شده) — با nonce و بررسی `manage_options`
- حذف دائمی، فقط با تیک «تأیید حذف دائمی»
- **دریافت CSV همین فیلتر** — با BOM UTF-8 برای اکسل فارسی، و بی‌خطرسازی مقادیر با شروع `= + - @` (جلوگیری از CSV injection)

همهٔ عملیات از `admin-post.php` با nonce و بررسی سطح دسترسی انجام می‌شود.

---

## ۶. برگه‌های تماس و درباره ما

- **`/contact-us/`** و **`/about-us/`** محتوای اصلی منبع را دارند (نه طراحی تازه). آدرس‌های قدیمی `/contact/` و `/about/` با ۳۰۱ به همین‌ها می‌روند تا برگهٔ تکراری ساخته نشود.
- فرم روی هر دو برگه با shortcode رسمی ساخته شده و مستقیم به `admin-post.php` می‌رود (بدون وابستگی به JavaScript).
- اطلاعات تماس از تنظیمات مرکزی خوانده می‌شود؛ در حالت `demo` برچسب «اطلاعات نمونه و غیرواقعی — لینک‌ها غیرفعال‌اند» نمایش داده می‌شود تا شمارهٔ ساختگی به‌عنوان شمارهٔ واقعی فروخته نشود.

---

## ۷. خبرنامه

`[mh_newsletter]` همان مسیر را دارد: در همان جدول با `type = newsletter` ذخیره می‌شود و ایمیل اجباری است. خبرنامه **ارسال انبوه** ندارد؛ فقط جمع‌آوری و CSV گرفتن. برای ارسال واقعی، فهرست را از CSV به سرویس ایمیل مارکتینگ منتقل کنید.
