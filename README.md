# موبایل هشتگ | MOBILE HASHTAG

فروشگاه فارسی راست‌به‌چپ برای گوشی، لوازم جانبی و گجت؛ با **HTML5، CSS3، JavaScript ماژولار، Node.js، Express و SQLite واقعی**. بدون وردپرس، فریم‌ورک فرانت‌اند، سرویس خارجی یا ذخیره‌سازی تجاری در localStorage.

> **حالت خرید آزمایشی:** حساب، سبد، علاقه‌مندی و سفارش واقعاً در دیتابیس ذخیره می‌شوند. هیچ مبلغی دریافت و هیچ کالایی ارسال نمی‌شود. این نسخه، مجوز آغاز فروش تجاری یا ادعای اتصال به درگاه پرداخت نیست.

## به‌روزرسانی نهایی تماس و ظاهر

اطلاعات تماس اکنون فقط در `backend/config/contact.json` تنظیم می‌شود و در صفحه تماس، خانه، فوتر و میانبر header استفاده می‌شود. نسخه تحویلی شامل **اطلاعات آزمایشی صریح** است: شماره‌های رزروشدهٔ نمایشی، دامنه‌های `.example` و نشانی خیالی. لینک‌های نمونه عمداً غیرفعال‌اند؛ با ثبت اطلاعات واقعی و `mode: "live"`، لینک‌های معتبر فعال می‌شوند. فیلد خالی مخفی می‌شود و نقشه بدون مختصات تأییدشده نمایش داده نمی‌شود.

- [راهنمای تغییر اطلاعات تماس](docs/CONTACT-SETTINGS.md)
- [خلاصه تغییرات](docs/CHANGELOG.md)
- [نتایج آزمون این به‌روزرسانی](docs/CONTACT-TEST-REPORT.md)

طراحی تأییدشده، هر ۲۱ صفحه، ۴۷ دسته و ۲۸ محصول و منطق خرید حفظ شده‌اند. تغییر اطلاعات تماس، حالت پرداخت آزمایشی را به پرداخت واقعی تبدیل نمی‌کند. دستورهای نصب تغییر نکرده‌اند.

## اجرای سریع در ویندوز

۱. **Node.js نسخه 22.13 یا جدیدتر** نصب کنید. نسخه آزمایش‌شده: `22.22.3`. نسخه LTS جدید نیز پیشنهاد می‌شود. SQLite داخل Node استفاده می‌شود؛ نصب MySQL، SQLite، Python یا ابزار کامپایل لازم نیست.

۲. ZIP را استخراج کنید و در پوشه `mobile-hashtag` یک پنجره PowerShell یا Command Prompt باز کنید.

۳. دقیقاً اجرا کنید:

```powershell
npm ci --omit=dev
npm run setup
npm start
```

۴. مرورگر را در نشانی زیر باز کنید:

```text
http://localhost:3000
```

`setup` به‌صورت خودکار `.env` را از نمونه می‌سازد، یک کلید نشست تصادفی اختصاصی ایجاد می‌کند و دیتابیس را با داده نمونه راه‌اندازی می‌کند. اجرای مجدد آن داده کاربران یا سفارش‌ها را حذف نمی‌کند. هیچ حساب ازپیش‌ساخته یا رمز پیش‌فرضی وجود ندارد؛ از صفحه ثبت‌نام حساب بسازید.

برای توقف سرور `Ctrl+C` بزنید. برای اجرای بعدی فقط `npm start` لازم است. فایل‌های HTML را با دوبار کلیک و `file://` اجرا نکنید؛ API و نشست به سرور نیاز دارند.

**اگر می‌خواهید تنظیمات را خودتان پیش از setup تغییر دهید:**

```powershell
Copy-Item .env.example .env
notepad .env
npm run setup
npm start
```

در Command Prompt به‌جای `Copy-Item` از `copy .env.example .env` استفاده کنید. در Linux/macOS همان دستورهای npm کار می‌کنند؛ کپی اختیاری با `cp .env.example .env` انجام می‌شود.

### نکات اجرا

- پورت پیش‌فرض `3000` است؛ در `.env` قابل تغییر است.
- `DATABASE_PATH=database/store.sqlite` محل دیتابیس پایدار است.
- کلید `SESSION_SECRET` را بین اجراها ثابت نگه دارید تا نشست‌ها بازیابی شوند. بدون `.env`، حالت توسعه از کلید موقت استفاده می‌کند؛ بنابراین `setup` را اجرا کنید.
- هشدار `ExperimentalWarning: SQLite` در Node 22.22.3 مربوط به وضعیت ماژول داخلی Node است و در اجرای آزمون‌ها خطا محسوب نشده است.
- فونت، تصویر، آیکن و اسکریپت مرورگر همگی محلی‌اند. پس از نصب، اجرای فروشگاه نیازی به CDN ندارد.

## آنچه پیاده‌سازی شده است

- هویت سفید و طلایی؛ نشان اختصاصی موبایل/هشتگ، لوگوی افقی، لوگوی موبایل و favicon PNG.
- فونت محلی Vazirmatn، صفحه‌آرایی RTL و قیمت‌های تومان با ارقام فارسی.
- خانه کامل با ۴ اسلاید، بنرهای تبلیغاتی، ۱۲ کارت دسته، چند گرید، دو کاروسل محصول، برندها، نظرات نمونه، مجله و خبرنامه.
- **۲۸ محصول نمونه:** ۱۰ محصول اصلی خواسته‌شده و ۱۸ محصول تکمیلی برای مرتبط و غیرخالی بودن همه دسته‌ها.
- **۴۷ دسته:** ۴ والد و ۴۳ زیردسته؛ رابطه چندبه‌چند با محصول، تصویر و URL مستقل برای هر دسته.
- **۲۱ فایل HTML مستقل** شامل تمام صفحات اصلی، مقاله، پیگیری و خطای ۴۰۴. صفحه دسته‌بندی از پارامتر slug استفاده می‌کند؛ هر دسته URL و داده مستقل دارد، نه فایل تکراری مستقل.
- جست‌وجو، فیلتر برند/قیمت/موجودی/تخفیف، پنج مرتب‌سازی، شمارش و صفحه‌بندی در سرور.
- جزئیات محصول با گالری، برش جزئیات، بزرگ‌نمایی، انتخاب رنگ و تعداد، مشخصات، نظرات واقعی کاربران و محصولات مرتبط/اخیراً دیده‌شده.
- سبد و علاقه‌مندی پایدار؛ ادغام سبد مهمان هنگام ورود، حذف و تغییر تعداد.
- ثبت‌نام، ورود، خروج، پروفایل، تغییر رمز، نشانی‌ها، تاریخچه و جزئیات سفارش.
- سفارش تراکنشی SQLite: قیمت سرور، کنترل موجودی، کاهش موجودی اتمیک، snapshot اقلام و نشانی، کلید idempotency برای جلوگیری از سفارش تکراری.
- پیگیری با کد تصادفی و شماره موبایل گیرنده؛ اطلاعات خصوصی نشانی در پاسخ عمومی نمایش داده نمی‌شود.
- ذخیره پیام تماس، اشتراک خبرنامه و دیدگاه محصول در دیتابیس.
- اعلان‌های فارسی، تأیید حذف سفارشی، حالت خالی، loading، منوی موبایل، مگامنو و پشتیبانی reduced motion.

## محیط توسعه و آزمون

برای توسعه، ابزار تولید دارایی و آزمون مرورگر، وابستگی‌های توسعه را هم نصب کنید:

```powershell
npm ci
npm test
npx playwright install chromium
npm run test:ui
npm run format:check
```

- آزمون API دیتابیس جداگانه `test-results/api-test.sqlite` می‌سازد.
- آزمون UI سرور جداگانه پورت `3100` و دیتابیس `test-results/ui-test.sqlite` را استفاده می‌کند.
- آزمون‌ها داده فروشگاه اصلی را تغییر نمی‌دهند؛ پوشه `test-results` قابل حذف است.
- در محیط محدود Arena از Chromium بسته‌بندی‌شده استفاده شده است: `ARENA_BROWSER=1 npm run test:ui` (در PowerShell: `$env:ARENA_BROWSER="1"`). برای ویندوز معمولی این متغیر را تنظیم نکنید.
- `npm run assets` همه خروجی‌های تصویری قابل‌بازتولید را از فایل‌های محلی می‌سازد؛ PNGهای اصلی AI همراه پروژه‌اند. فراخوانی سرویس تصویر خارجی انجام نمی‌شود.
- `npm run dev` اجرای watch است. بازتولید صفحات با `python scripts/pages.py` فقط ابزار اختیاری توسعه است؛ اجرای فروشگاه به Python نیاز ندارد. پس از آن `npm run format` اجرا شود.

جزئیات آزمون‌های واقعاً انجام‌شده: [docs/TEST-REPORT.md](docs/TEST-REPORT.md).

## ساخت بسته ZIP

پس از نصب کامل وابستگی‌های توسعه:

```powershell
npm run package
```

خروجی: `deliverables/mobile-hashtag.zip` و فایل `SHA256.txt`.
ZIP شامل کد، schema، seed، تصاویر اصلی و بهینه، فونت و مجوز، آزمون‌ها و مستندات است. `.env`، دیتابیس‌های دارای اطلاعات شخصی، `node_modules`، `.git` و screenshotهای آزمون در ZIP قرار نمی‌گیرند. گیرنده با دستورهای اجرای سریع، دیتابیس تازه می‌سازد.

## امنیت و داده

- bcrypt با cost=12؛ رمز حداقل ۱۰ کاراکتر و حداکثر ۷۲ بایت برای جلوگیری از truncation bcrypt.
- نشست امضاشده و ذخیره‌شده در SQLite، کوکی HttpOnly و SameSite=Lax، چرخش شناسه پس از ورود، Secure در production.
- CSRF برای همه mutationها، پارامترهای SQL آماده، محدودیت حجم JSON، rate limit برای احراز هویت و فرم‌های حساس.
- مالکیت حساب/سفارش/نشانی بررسی می‌شود؛ قیمت ورودی کلاینت نادیده گرفته می‌شود.
- CSP بدون inline script، escape داده کاربر در HTML، headerهای امنیتی Helmet.
- اطلاعات مشتری یا سفارش در localStorage ذخیره نمی‌شوند. recently viewed نیز در نشست سرور است.
- رنگ‌ها انتخاب نمایشی محصول‌اند؛ **موجودی مشترک محصول** دارند، نه موجودی جداگانه برای هر رنگ.
- بکاپ دیتابیس باید با توقف سرور یا ابزار backup سازگار SQLite/WAL انجام شود؛ کپی‌کردن تنها فایل اصلی هنگام نوشتن، روش مطمئنی نیست.

## مرز نسخه فعلی و پیش‌نیازهای انتشار تجاری

قابلیت‌های نرم‌افزاری فوق واقعی‌اند، اما داده تجاری و پرداخت نمونه هستند. پیش از فروش واقعی لازم است:

1. درگاه پرداخت مجاز، تأیید سمت سرور، callback/webhook معتبر، ثبت پرداخت و استرداد به چرخه سفارش متصل شود. اکنون تنها `demo_confirmed` وجود دارد.
2. قیمت، موجودی، تصاویر مستند، گارانتی و رجیستری توسط صاحب فروشگاه تأیید شود. تصاویر فعلی تبلیغاتی AI/SVG هستند؛ تصویر جزئیات، crop همان نمای اصلی است نه عکس زاویه مستقل.
3. نشانی/تلفن واقعی، اطلاعات حقوقی، مجوزها، شرایط بازگشت و سیاست حریم خصوصی نهایی درج شود. نشان اعتماد یا مجوز جعلی ارائه نشده است.
4. ایمیل/پیامک، تأیید ایمیل و بازیابی رمز متصل شوند. فرم تماس و خبرنامه اکنون فقط ذخیره می‌کنند.
5. ابزار مدیریت عملیاتی کاتالوگ/سفارش، ارسال، مالیات، انبار و پشتیبان‌گیری انتخاب شود. پنل ادمین در دامنه صفحات درخواستی نبود و ساخته نشده است.
6. HTTPS، کلید نشست اختصاصی، دامنه و reverse proxy مورد اعتماد، پایش، سیاست نگهداری/حذف داده و بررسی امنیتی مستقل برقرار شود. نرخ‌محدودسازی فعلی در حافظه هر process است؛ برای چند replica به store مشترک نیاز دارد.
7. در production، `NODE_ENV=production` بگذارید؛ HTTP ساده برای کوکی Secure کافی نیست. فقط در پشت proxy مورداعتماد `TRUST_PROXY=1` تنظیم کنید. در development اجازه embed برای پیش‌نمایش فعال است؛ در production frame policy محدود می‌شود.

این موارد به‌عنوان قابلیت متصل‌شده یا آزموده‌شده ادعا نشده‌اند. اجرای واقعی روی Windows و Safari/Firefox نیز در این محیط انجام نشده؛ دستورهای ویندوز بر پایه اسکریپت‌های مستقل از سیستم‌عامل ارائه شده‌اند.
